# 语航 v1.4.4：切换会话后目录高亮正常、正文跳转失效的修复设计

## 1. 背景与目标

当前 ChatGPT Prompt Navigator v1.4.3 在网页完整刷新后通常可以导航；但通过 ChatGPT 自身侧栏切换到其他对话后，插件虽然仍能读取、展示“我的提问”目录，点击目录或按 `Alt + ↑/↓` 也会改变高亮，却可能无法滚动到对应提问；插件的 `↻` 强制重新读取对话后，状态仍可能显示“当前0/N”，问题不会恢复。有时不重新加载网页也会自行恢复。

**v1.4.4 目标**：在单页应用（SPA）切换聊天、同时挂载多个聊天滚动容器、消息节点可能隐藏或虚拟化的情况下，可靠地识别当前活动会话、滚动容器与可定位锚点，保持点击和快捷键导航一致；遇到不可定位状态时有明确、受控的恢复与失败行为，不出现“高亮已切换但实际导航误报成功”的情况。

- GitHub 仓库：`LynFrost/Yuhang`
- 开发分支：`feature/v1.4.4`（仓库现有开发分支）
- 基线：`main` 的 v1.4.3
- 文档：`docs/v1.4.4-conversation-switch-navigation-fix.md`
- 计划版本：v1.4.4
- **本阶段仅提交需求和设计文档，不修改 `content.js`、`manifest.json`、README、样式或其他代码。**

## 2. 复现步骤和可观测事实

1. 打开 ChatGPT，对话 A 中插件能导航。
2. 使用 ChatGPT 自身界面切换到另一段较长的对话 B，不整页刷新。
3. 插件能显示 B 的提问目录；但点击项目或 `Alt + ↑/↓` 时，目录高亮变化，正文滚动位置不变。
4. 部分场景显示“当前0/N”。点击插件 `↻` 后仍为“当前0/N”，导航继续失效。
5. 同一对话过一段时间可能自行恢复。

### 2.1 用户在失败会话中的只读 Console 检测

**DOM 消息结构：**

| 检测项 | 观测值 |
| --- | ---: |
| `userUnits` 的 ID 数 | 12 |
| `turnElements` 的 ID 数 | 12 |
| 两类 DOM ID 的交集 | 12 |
| `getBoundingClientRect().height > 0` 的用户单元数 | 0 |
| 同条件的 turn 数 | 0 |

**页面中 `.thread-scroll-container` 的情况：**

| DOM 序号 | clientHeight | scrollHeight | scrollRange | scrollTop | flexDirection | 包含用户单元 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 0 | 0 | 0 | 0 | 0 | column | 是 |
| 1 | 0 | 0 | 0 | 0 | column | 否 |
| 2 | 0 | 0 | 0 | 0 | column | 否 |
| 3 | 2946 | 32935 | 29989 | 约 29988.8 | column | 是 |

这些数值来源于一次真实页面状态，不是全局恒定值。**特别注意**：两种 DOM 消息属性的 ID 相互一致，不代表它们已与插件通过会话 API 获取的消息 UUID 一致；后者尚未单独验证。零高度也不能单凭数值认定节点“损坏”，可能是非活动会话、虚拟化占位或布局阶段。

### 2.2 代码证据（v1.4.3）

- `content.js` 的 `primaryScrollContainer()`（约 705 行）使用 `document.querySelector(".thread-scroll-container")`，只选择第一个匹配元素，未验证它是否可见、属于当前会话、可滚动。
- `currentMountedPromptEntries()`（约 375–408 行）按 DOM 消息 ID 绑定索引，并过滤 `rect.height <= 0` 的节点，实测场景下因此可能得到 0 个可用锚点。
- `resolvePromptElement()`（约 364–373 行）会尝试 UUID 节点、turn 节点、旧 DOM 节点、文本回退；并非所有回退都确保目标属于当前活动容器且可用于滚动。
- `jumpTo()`（约 945–968 行）先设置选中项并更新目录高亮，再尝试实际定位；高亮变化不能说明滚动成功。
- `scrollOneViewport()`（约 767–802 行）当选中的容器滚动距离为 0 时会返回 false；`runNavigation()`（约 877–943 行）遇到没有位移会结束。
- `currentPromptIndex()`（约 970–1008 行）在无锚点、无有效选中项时返回 0；`navigationDirection()`（约 820–848 行）可能以错误起点推断滚动方向。
- `resetForRoute()` / `prefetchConversation(false)`（约 1082–1110、430–481 行）处理会话切换和索引读取；`↻` 触发 `prefetchConversation(true)`，但只强制重新读取 API，不负责修复错误滚动容器或锚点可见性。

### 2.3 目前可以下的结论与待验证项

**已经有直接证据**：同页存在 4 个同类滚动容器，而插件总是取第一个；实测第一个无尺寸、无滚动范围，第四个有活动滚动范围。这在需要渐进滚动时是一条确定的失败路径。

**待进一步验证**：为什么用户消息节点全部为零高度、它们是否属于隐藏的旧会话或虚拟化结构；是否存在 API UUID 与 DOM UUID 不一致；即使选中正确滚动容器是否还需调整锚点定位。不要把一个已识别缺陷直接视作所有症状的唯一原因。

## 3. 需求和设计建议（实施前应按真实 DOM 结果验证）

### 3.1 选择正确的活动滚动容器（P0）

- 不再使用“第一个 `.thread-scroll-container`”作为无条件首选。
- 统一 `primaryScrollContainer()`、渐进滚动、当前位置判断使用同一套“活动会话容器”判定。
- 枚举候选容器，检查与当前可见聊天主区域的关联、元素是否连接到文档、容器/祖先是否有实际可见尺寸、真实可滚动范围、是否包含当前会话的用户消息或有效节点；不要仅按 DOM 序号、最大 `scrollHeight` 或最后一个元素选择。
- 若多个候选均符合条件，应使用明确、可测试的选择规则；若当前没有可靠候选，返回“待就绪/不可定位”状态，而非静默回退到已知无效的容器。
- 兼容现有 `column-reverse` 负区间，以及实测 `column` 普通正区间；滚动边界和方向必须使用**实际选中容器**的布局值。
- 当 SPA 切换使 DOM 或活动容器变化时，允许重新解析，不长期缓存旧 DOM 元素引用。

### 3.2 活动会话锚点识别（P0）

- 仅在当前活动会话/滚动容器范围内建立锚点索引，不从隐藏会话的同名节点中误取目标。
- 优先验证消息 UUID 与当前会话 API 索引是否一致；兼顾 `data-chatgpt-search-message-ids` 和 `data-turn-key` 的结构。
- 区分“DOM 内存在节点”“节点有尺寸”“节点可作为当前活动聊天的滚动锚点”，不要把数量混为一谈。
- 尽量基于实际可见消息节点或可用锚点定位；对零高度节点应识别其来源并决定跳过/转用有效祖先/渐进寻找，不能不经验证直接对隐藏节点 `scrollIntoView()`。
- `当前x/N` 含义保持清楚：`x` 代表当前可直接绑定的活动会话锚点数；即使 `x=0`，也应允许受控的渐进寻找，而不是自动宣告全部无法导航。
- 如果没有有效锚点，不能使用无关会话的锚点作回退。

### 3.3 零锚点导航与方向兜底（P0）

- `currentPromptIndex()` 没有定位依据时，不要把“未知位置”强制等同索引 0。
- 根据实际选中容器的滚动边界、已知锚点、先前可靠的位置及尝试方向决定起点；方向未知时采用有界、可取消的查找策略，不能无限往错误边界滚动。
- 需要处理初始位于聊天底部、顶部、长助手回复中间、不同布局方向、无锚点与部分锚点等情况。
- 对没有进展、目标未出现、达到滚动边界、用户手动操作等情况给出确定退出条件，避免无限循环、来回弹跳或意外回到底部。
- 每次新跳转取消旧的异步导航；切换聊天时旧会话的导航必须失效，不能作用于新会话。

### 3.4 导航反馈与自动同步（P1）

- 区分“已选中目录项”“正在寻找目标”“找到有效目标并完成滚动”“无法定位/取消”，避免只高亮但无反馈。
- 在不破坏原有快捷键的前提下，鼠标跳转、`Alt + ↑/↓`、`Alt + Home/End` 走同一个有效定位路径。
- 会话切换后等待活动视图就绪再初始化/验证定位；只有在明确检测到索引缺失或 UUID 不匹配时，才考虑有限次数的 API 重新读取。
- 不要通过每次 DOM 变化无条件请求 API、频繁强制刷新或任意固定延时来掩盖滚动容器错误；控制请求量以避免 429。
- 必要的调试日志仅记录数量、状态、容器尺寸和是否匹配，不输出提问文本、消息 UUID、token 或会话内容。

## 5. 验收与回归测试

### 5.1 必须通过的操作测试

- [ ] 网页首次进入会话 A，目录、点击、上下/首末快捷键均正常。
- [ ] 不刷新页面，从 A 切换到 B，再切到 C，分别点击靠前、中间、靠后的提问，正文能到达正确目标。
- [ ] B/C 各自能显示完整提问目录，切换时不会沿用 A 的 UUID 或滚动位置。
- [ ] 同时存在至少 4 个 `.thread-scroll-container`，前三个无实际滚动范围、第四个可滚动时，定位仍能操作活动容器。
- [ ] 活动容器为 `column`，`scrollTop` 在顶部、中间、底部时，导航正确。
- [ ] 活动容器为 `column-reverse` 时，顶部、中间、底部导航正确。
- [ ] `当前0/N` 时，插件能在可用范围内渐进寻找目标；不能定位时有明确反馈，不出现错误高亮/误跳。
- [ ] 消息 DOM 节点存在但全部零高度时，不误用隐藏会话节点；节点随后变为可用时可自动恢复定位。
- [ ] 点击目录和 `Alt + ↑/↓` 高亮与真实正文位置一致；`Alt + Home/End` 同样可用。
- [ ] 新点击取消旧导航；人工滚轮/触摸/点击聊天取消导航；切换会话取消旧会话导航。
- [ ] 插件 `↻` 在正常和异常会话中都不导致目录丢失、频繁请求或卡死。
- [ ] 连续多次 A/B/C 切换、超长虚拟化聊天、短聊天、筛选状态和侧边栏收起/展开回归正常。

### 5.2 状态与安全约束

- [ ] “当前x/N”与可直接定位的活动会话锚点一致，状态说明不会暗示 `0/N` 必然错误。
- [ ] 无效容器不会被选择为滚动目标；无可用容器时明确停止，不修改其他聊天区域的位置。
- [ ] 不发出额外第三方请求，不新增权限，不记录聊天内容或访问令牌。
- [ ] 版本号、README 和实际功能一致；主分支 `main` 在开发与审查期间保持不变。
